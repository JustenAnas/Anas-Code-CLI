# Common Errors

This guide covers common problems you may encounter while installing, configuring, and using ANAS CLI.

## Node.js version error

**Problem:** ANAS CLI reports that Node.js 18 or higher is required.

**Solution:**

1. Check your installed version:

   ```bash
   node -v
   ```

2. Install a supported Node.js version if necessary.
3. Restart your terminal and try again.

## API key is missing

**Problem:** ANAS CLI reports that the selected provider's API key is not configured.

**Solution:**

1. Create or check your `.env` file in the project root.
2. Confirm that the environment variable matches your selected provider.

   | Provider   | Environment variable |
   | ---------- | -------------------- |
   | Claude     | `ANTHROPIC_API_KEY`  |
   | OpenAI     | `OPENAI_API_KEY`     |
   | OpenRouter | `OPENROUTER_API_KEY` |
   | Gemini     | `GEMINI_API_KEY`     |
   | Groq       | `GROQ_API_KEY`       |

3. Restart the CLI after changing environment configuration.

Keep your API keys private and never commit them to version control.

## Invalid API key or authentication error

**Problem:** The provider rejects your API key.

**Solution:**

* Check that the key is copied correctly.
* Confirm that the key belongs to the selected provider.
* Verify that the key is active and has the necessary permissions.
* Check the provider's account or billing dashboard if access or credits are required.

The `doctor` command reports whether API keys are configured, but a configured key is not necessarily valid.

## OpenRouter model selection fails

**Problem:** ANAS CLI cannot load the OpenRouter model list or finds no eligible models.

**Solution:**

1. Confirm that `OPENROUTER_API_KEY` is configured correctly.
2. Check your internet connection and OpenRouter service status.
3. Verify that your account and key can access the API.
4. Try again later if the model list cannot be retrieved.

The guided setup filters for text-only models that support tool calling.

## Provider request fails

**Problem:** A request fails while generating a response.

**Solution:**

* Check your internet connection.
* Verify your API key and account status.
* Confirm that the selected model is available.
* Check provider rate limits and usage limits.
* Review the error message for provider-specific details.

## A tool cannot access a file

**Problem:** A file-reading or file-editing operation fails.

**Solution:**

* Check that the path exists.
* Verify the spelling and file extension.
* Use a path relative to your project when practical.
* Confirm that the file is inside the permitted workspace.
* Check whether the operation was blocked by a safety rule.

File operations can be restricted when a path is outside the permitted workspace.

## A tool operation is denied

**Problem:** ANAS CLI does not execute a command or modify a file.

**Solution:**

* Review the permission prompt and confirm whether the operation was approved.
* Check whether the selected mode allows the tool.
* Inspect the operation details and any guardrail message.
* If the operation is destructive or affects protected paths, review the restrictions before trying again.

Ask mode is limited to read-only tools. Agent mode provides broader tool access, subject to permission checks and guardrails. Plan mode currently has no tools enabled.

## Repeated tool failures

**Problem:** ANAS CLI stops retrying an operation.

**Solution:**

Inspect the error output, check the path or command, and change the operation before trying again. ANAS CLI stops retrying an identical operation after three failures.

## Terminal command does not work

**Problem:** A terminal command fails when executed through the `bash` tool.

**Solution:**

The current implementation executes commands through the Windows command shell. Use Windows-compatible syntax and check whether the command depends on Unix-specific utilities or flags.

For example:

```cmd
dir
type package.json
git status
```

## Cloud login issues

**Problem:** Logging in to ANAS Cloud or logging out does not work as expected.

**Solution:**

* Check your internet connection.
* Retry the relevant command:

  ```bash
  npm run dev -- login
  ```

  ```bash
  npm run dev -- logout
  ```

* Read any authentication error returned by the CLI.

## Verbose usage information is missing

**Problem:** Token usage or estimated cost is not displayed.

**Solution:**

Use the `--verbose` option with a supported command:

```bash
npm run dev -- wakeup --verbose
npm run dev -- chat --verbose
npm run dev -- talk "Explain this project" --verbose
```

Usage information depends on what the selected provider returns. Displayed costs should be treated as estimates.

## Still having trouble?

If the problem persists:

1. Run `npm run dev -- doctor`.
2. Check the provider configuration.
3. Read the complete error message.
4. Identify the command, provider, and operation that failed before investigating further.
