# Common Errors

Use this guide to troubleshoot common ANAS CLI setup and runtime problems. Start with the section that matches your error and follow the suggested steps.

## Missing API key

The `doctor` command currently checks for `ANTHROPIC_API_KEY`.

### Fix

1. Open the `.env` file in the ANAS CLI project root.
2. Add your Anthropic API key:

```bash
ANTHROPIC_API_KEY=your_anthropic_api_key
```

3. Save the file and rerun the check:

```bash
npm run dev -- doctor
```

The guided `wakeup` flow runs this environment check before provider selection.

**Note:** The doctor check validates the Anthropic key specifically. It does not validate credentials for every supported provider.

## Unsupported mode

If you see an error indicating that the mode is invalid, use one of the supported values:

- `agent`
- `ask`
- `plan`

For example, start an interactive chat in Ask mode:

```bash
npm run dev -- chat --mode ask
```

Check the spelling of the mode and make sure you're using the `--mode` option with the `chat` command.

## Provider or API errors

If a request fails or a provider returns an error, check the following:

- The selected provider's API key is configured in the root `.env` file.
- The key is valid and has the required access.
- Your internet connection is working.
- The provider's service is available.
- The selected model is supported by your provider configuration.

ANAS CLI supports Claude, OpenAI, OpenRouter, and Gemini.

Remember that the `doctor` command checks the Anthropic API key specifically, so a successful check does not guarantee that another provider is configured correctly.

## Chat commands

Use the built-in help command while an interactive chat session is running:

```text
/help
```

The following commands are available in the current implementation:

| Command | Purpose |
| --- | --- |
| `/help` | Display available chat commands. |
| `/exit` | Leave the current session. |
| `/new` | Start a new session. |
| `/history` | View stored sessions. |
| `/resume` | Select a previous session. |

## Tool operation blocked

A tool operation may be blocked for several reasons:

- You denied the permission prompt.
- A protected path requires authorization.
- A terminal command was rejected by destructive-command guardrails.
- The same operation failed three times.

### Fix

1. Review the requested operation and the affected path or command.
2. Check whether the operation requires permission or additional authorization.
3. Correct the underlying issue before retrying.
4. Review any changes before continuing.

Do not bypass a safety check without understanding why the operation was blocked.

## Still stuck?

When reporting a problem, include:

- The complete error message.
- The command you ran.
- Your selected provider.
- Your selected mode.
- The relevant steps that reproduce the issue.

**Protect your credentials:** Remove API keys, tokens, and other secrets before sharing logs or configuration files.
