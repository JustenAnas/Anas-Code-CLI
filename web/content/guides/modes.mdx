# Ask, Agent, and Plan Modes

ANAS CLI provides three interaction modes: **Ask**, **Agent**, and **Plan**.

Each mode has different capabilities and tool permissions.

## Select a mode

Start an interactive chat using the `--mode` option.

### Ask mode

```bash
npm run dev -- chat --mode ask
```

### Agent mode

```bash
npm run dev -- chat --mode agent
```

### Plan mode

```bash
npm run dev -- chat --mode plan
```

The default mode is `agent`.

## Ask mode

Ask mode is designed for understanding and exploring your codebase without modifying files.

Example prompts:

- Explain how this function works.
- Find where this API endpoint is defined.
- What does this error mean?
- Explain the authentication flow.
- Search for references to this function.

### Available tools

- `read_file`
- `search_code`
- `glob`
- `list_dir`

Ask mode cannot invoke file-writing, editing, terminal, or Git tools through its tool allowlist.

Use Ask mode when you want to investigate a project without making changes.

## Agent mode

Agent mode is designed for carrying out coding tasks.

Example prompts:

- Implement input validation.
- Fix this failing test.
- Create a new API endpoint.
- Refactor this component.
- Find and fix a bug.

### Available tools

Agent mode can access all eight registered tools:

| Tool | Purpose |
| --- | --- |
| `read_file` | Read project files. |
| `write_file` | Create or overwrite files. |
| `edit_file` | Modify existing files. |
| `bash` | Execute Windows CMD commands. |
| `glob` | Find files matching patterns. |
| `list_dir` | Inspect directories. |
| `search_code` | Search project code. |
| `git` | Inspect Git repository information. |

### Permissions

ANAS CLI requests confirmation before:

- Executing terminal commands
- Creating or overwriting files
- Editing existing files

Additional safety checks include:

- Workspace-boundary restrictions
- Protected files and directories
- Restricted package-management files
- Destructive-command guardrails
- Repeated tool-failure protection
- Secret redaction for detected sensitive content

Permission approval does not automatically bypass these restrictions.

See [Tools & Permissions](/docs/reference/tools).

## Plan mode

Plan mode is designed for discussing an implementation approach before making changes.

Example prompts:

- Outline the steps to add authentication.
- Design a database schema for this feature.
- Explain how to migrate this project to TypeScript.
- Propose an implementation strategy.

Plan mode currently has no registered tools enabled.

It can produce an implementation plan, but it cannot inspect or modify files through the tool system.

Use Agent mode when you're ready to implement the plan.

## Tool access comparison

| Capability | Ask | Agent | Plan |
| --- | --- | --- | --- |
| Answer questions | Yes | Yes | Yes |
| Read project files using tools | Yes | Yes | No |
| Search project code using tools | Yes | Yes | No |
| Create files | No | Yes, with permission | No |
| Edit files | No | Yes, with permission | No |
| Execute terminal commands | No | Yes, with permission | No |
| Inspect Git using tools | No | Yes | No |
| Generate implementation plans | Yes | Yes | Yes |

## Switch modes during a session

You can change modes without restarting ANAS CLI.

Switch to Ask mode:

```text
/mode ask
```

Switch to Agent mode:

```text
/mode agent
```

Switch to Plan mode:

```text
/mode plan
```

Display available slash commands:

```text
/help
```

Switching modes changes which tools are available for subsequent interactions.

## ANAS Cloud and interaction modes

ANAS Cloud authentication and local interaction modes are separate systems.

Cloud authentication determines whether you can access protected cloud services.

Interaction modes determine which local coding tools the agent can use.

ANAS Cloud currently includes an OpenAI integration using `gpt-4o`, supporting standard responses, streaming, and tool-call responses.

A cloud model returning a tool call does not automatically authorize its execution.

The CLI must still enforce the selected mode's tool restrictions, permission prompts, and safety guardrails.

Cloud OpenAI requests are limited to **30 requests per minute per authenticated user**.

See [ANAS Cloud](/docs/guides/anas-cloud) and [Security](/docs/guides/security).

## One-shot prompts

The `talk` command sends a single prompt without starting an interactive chat session.

```bash
npm run dev -- talk "Explain this project"
```

The `talk` command does not currently accept a `--mode` option.

For explicit mode selection, use `chat --mode`.

## Important limitations

- Ask mode is read-only through its registered tool allowlist.
- Agent mode can modify files, but permission checks and guardrails still apply.
- Plan mode currently has no registered tools.
- Tool results should be treated as untrusted data.
- Agent responses should distinguish verified tool results from assumptions.
- A successful cloud login does not grant additional local tool permissions.
