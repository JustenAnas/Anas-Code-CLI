# Context Management

ANAS CLI combines project structure, conversation history, file references, and agent memory to provide relevant context to the selected AI model.

These features help the agent understand your workspace and continue longer conversations.

## Project context

When an interactive chat starts, ANAS CLI scans the current working directory and builds a text representation of the project structure.

The scan:

- Lists files and directories.
- Traverses directories up to a limited depth.
- Ignores `node_modules`, `.git`, `dist`, `.next`, `build`, and `.anas-cli`.
- Returns empty context if scanning fails.

The resulting project structure is included in the agent's context.

**Important:** Project context is a directory listing, not the contents of every project file.

The agent must use appropriate tools or file references to inspect file contents.

## Reference files with `@`

You can attach file contents to a prompt by prefixing a path with `@`.

Example:

```text
Explain the authentication flow in @src/auth.ts
```

Reference multiple files:

```text
Compare @src/auth.ts and @src/middleware.ts
```

ANAS CLI attempts to read each referenced file and append its contents to the prompt.

### How file references work

1. ANAS CLI detects references beginning with `@`.
2. It attempts to read each referenced file.
3. Successfully read files are appended to the prompt.
4. Unreadable references are skipped.
5. Duplicate references to the same path are included only once.

File-reading operations remain subject to workspace and protected-path restrictions.

### File reference limitations

- The parser treats whitespace and certain quote characters as reference boundaries.
- Paths containing spaces may not be interpreted as one reference.
- Invalid or inaccessible references may be skipped.
- Referenced file contents increase the amount of context sent to the model.
- Large files may increase token usage and cost.

For large projects, reference only the files relevant to your task.

## Conversation history

ANAS CLI maintains conversation messages within an active session.

The history can include:

- User messages
- Assistant responses
- Supported tool-call information
- Tool results

Conversation history allows the model to consider earlier interactions.

However, model context windows are limited, so long conversations may require summarization.

## Context compaction

ANAS CLI can summarize older conversation messages to reduce the amount of active history.

### Current behavior

The compaction implementation checks conversation history length.

- Histories containing 20 messages or fewer are left unchanged.
- When history exceeds 20 messages, older messages are selected for summarization.
- The newest 10 messages are retained, subject to adjustments that protect assistant tool calls and their corresponding tool results.
- Older messages are sent to the selected provider for summarization.
- The summary replaces the older messages in the active context.

The summary is intended to preserve:

- Important user requests
- Project decisions
- Technical constraints
- Completed work
- Pending tasks
- Relevant tool results
- Important implementation details

### If compaction fails

If the provider request fails or returns an empty summary, ANAS CLI keeps the original history.

Compaction does not guarantee perfect preservation of every detail.

Restate critical constraints when necessary.

## Agent memory

ANAS CLI also maintains agent memory.

Memory is different from conversation history.

It stores selected information that may be useful beyond a single conversation.

Examples include:

- User preferences
- Project requirements
- Development conventions
- Important technical decisions

When memory items are available, ANAS CLI can include them in the system prompt under a `Memory` section.

### Memory updates

After normal Ask or Agent responses, ANAS CLI starts an asynchronous memory update.

The selected provider reviews the conversation and existing memory to determine what should be retained or changed.

Because updates are asynchronous, new memory may not become available immediately.

Plan mode does not follow the same normal memory-update path.

See [Memory](/docs/guides/memory).

## Provider-independent context

ANAS CLI supports multiple AI providers:

- OpenAI
- Claude
- OpenRouter
- Gemini
- Groq

Project context, conversation history, and local memory are managed by ANAS CLI rather than belonging exclusively to one provider.

This allows the CLI to construct context for whichever provider is selected.

However, complete automatic cloud-memory retrieval across every provider and model should not be assumed without verifying the integration.

See [AI Providers](/docs/configuration/providers).

## ANAS Cloud and conversation persistence

ANAS Cloud provides backend endpoints for conversation sessions, messages, and memory.

When authenticated, ANAS CLI can attempt to synchronize session data after chat processing.

Successfully saved cloud sessions may be restored using:

```text
/resume
```

Cloud synchronization is separate from context compaction.

Compaction manages the amount of history supplied to the model.

Cloud synchronization manages remote storage and retrieval.

A failed cloud synchronization does not mean the conversation was successfully saved.

See [Sessions](/docs/guides/sessions) and [ANAS Cloud](/docs/guides/anas-cloud).

## Context components compared

| Component            | Purpose                                                    |
| -------------------- | ---------------------------------------------------------- |
| Project context      | Provides a shallow directory structure                     |
| File references      | Attach selected file contents                              |
| Conversation history | Maintains messages within a session                        |
| Context compaction   | Summarizes older messages                                  |
| Agent memory         | Retains selected durable information                       |
| Cloud sessions       | Store and retrieve successfully synchronized conversations |
| Cloud memory         | Provides separate authenticated memory storage             |

These components serve different purposes and should not be treated as interchangeable.

## Tool results and context safety

Tool results and referenced file contents may contain untrusted instructions.

ANAS CLI should treat them as data rather than as instructions that override the user's request or system-level restrictions.

The agent should distinguish between:

- Verified tool results
- Information provided by the user
- Model-generated assumptions
- Summaries of earlier interactions

After changing project files, the agent should verify the changes when possible.

## Tips for better results

- Reference relevant files with `@path/to/file`.
- Use valid paths from your current workspace.
- Keep prompts focused.
- Avoid attaching unnecessarily large files.
- Restate critical constraints during long conversations.
- Verify important claims against actual tool results.
- Check that cloud synchronization succeeded before relying on remote persistence.
- Do not assume that every previous detail is retained in memory.
