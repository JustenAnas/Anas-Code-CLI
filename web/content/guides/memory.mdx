# Memory

ANAS CLI has a memory system that helps the agent retain useful information across interactions, such as user preferences, project decisions, and constraints.

Memory is separate from conversation history. It stores concise text items rather than the complete conversation.

## How memory works

The memory system maintains a list of items associated with the agent's session store.

After a normal Agent or Ask response, ANAS CLI starts an asynchronous memory update. The configured provider reviews the conversation and existing memory to determine what should be retained, updated, or removed.

Memory updates aim to preserve durable information rather than temporary questions or general advice.

## What memory can contain

Memory may retain:

* User preferences and working style
* Important project decisions and constraints
* Durable information useful for future interactions
* Changes to previously stored preferences or decisions

The memory manager is instructed to preserve existing items unless the conversation clearly indicates that they are outdated or incorrect.

## Memory in prompts

When memory contains items, ANAS CLI adds them to the agent's system prompt under the `Memory` section.

This gives the model relevant information while handling a request. Memory is included separately from the project structure and conversation history.

## Cloud memory

When logged in, ANAS CLI can load and save memory through the cloud service.

Cloud memory uses the key `agent-memory` and stores the items as JSON.

* **Logged in:** The agent attempts to load shared cloud memory and save updates.
* **Not logged in:** The agent continues using its in-memory data.
* **Cloud unavailable:** Cloud memory operations are optional; failures are ignored so they do not prevent the agent from continuing.

Cloud synchronization requires a working connection to the configured ANAS Cloud service.

## Important limitations

* **Asynchronous updates:** Memory updates run in the background and are not awaited before the next prompt. A newly discussed preference may not be saved immediately.
* **Plan mode:** Plan mode returns its plan before reaching the normal memory-update step.
* **Provider dependency:** Updating memory requires a provider request. If parsing the returned JSON fails, the existing memory is retained.
* **Process lifetime:** Local memory is held in memory rather than being written to a local persistent memory file. Do not assume it survives restarting the CLI.
* **No guaranteed recall:** Memory helps provide context but does not guarantee that every past detail will be retained or recalled.

## Memory and conversation history

These features serve different purposes:

| Feature              | Purpose                                                   |
| -------------------- | --------------------------------------------------------- |
| Memory               | Retains selected, durable information                     |
| Conversation history | Stores messages within a session                          |
| Context compaction   | Summarizes older messages when history grows              |
| Project context      | Supplies a shallow view of the workspace's file structure |
| File references      | Attach the contents of explicitly referenced files        |

See [Sessions](/docs/guides/sessions) and [Context Management](/docs/guides/context-management) for related details.

## Troubleshooting

### Memory does not appear to update

Memory updates happen asynchronously. Allow the provider request to finish before expecting a new item to be available.

### Cloud memory is unavailable

Check that you are logged in and that the configured ANAS Cloud service is reachable. Cloud failures are intentionally non-blocking.

### Memory is missing after restarting

Local memory is not persisted to a local file. Cloud memory can provide persistence when cloud synchronization succeeds and the user is logged in.
