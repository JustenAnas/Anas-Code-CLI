# Sessions & Conversation History

ANAS CLI organizes interactive conversations into sessions.

Sessions allow you to start new conversations, review history, resume previous chats, and synchronize conversations with ANAS Cloud.

## How sessions work

When you start an interactive chat, ANAS CLI creates a new session automatically.

Each session tracks:

- **Session ID:** A unique identifier.
- **Creation time:** When the session was created.
- **Last update:** When the session was last modified.
- **Messages:** Conversation history, including supported tool-call information.
- **Memory:** Agent memory shared across sessions within the current chat process.

Session history and agent memory are separate features.

## Start a new session

Use `/new` inside an interactive chat:

```text
/new
```

ANAS CLI creates a fresh session and makes it active.

The previous session remains available within the current CLI process.

Starting a new session does not automatically delete previous conversations.

## View conversation history

Use `/history`:

```text
/history
```

ANAS CLI displays locally available sessions, including:

- Session ID
- Last-update timestamp
- Message count

The `/history` command lists sessions held by the current CLI process.

It does not directly list every session stored in ANAS Cloud.

## Resume a conversation

Use `/resume`:

```text
/resume
```

ANAS CLI presents eligible local sessions and, when authenticated, available cloud sessions.

### Resume a local session

Select a session marked `[Local]`.

ANAS CLI restores the conversation from the current process's session storage.

Local sessions are currently maintained in memory rather than a persistent local session database.

After the CLI process exits, those local sessions are no longer available unless they were successfully synchronized to the cloud.

### Resume a cloud session

Select a session marked `[Cloud]`.

ANAS CLI retrieves the saved conversation from ANAS Cloud.

Cloud restoration requires authentication.

Sign in using:

```bash
npm run dev -- login
```

When a cloud session is restored:

1. ANAS CLI retrieves the selected session.
2. Saved messages are loaded into a local session object.
3. Session timestamps are restored.
4. System-role messages are excluded from the restored conversation history.
5. The restored session becomes available for continued interaction.

Cloud session availability depends on successful synchronization, authentication, and network connectivity.

## ANAS Cloud synchronization

ANAS CLI supports synchronizing conversations with ANAS Cloud.

When you're authenticated, the CLI attempts to synchronize conversation data after processing a chat interaction.

### Synchronization process

1. The CLI identifies the active session.
2. Session metadata is sent to ANAS Cloud.
3. The metadata includes the local session ID and working directory.
4. A session title is derived from the first user message, using up to its first 80 characters.
5. Conversation messages are synchronized, including supported tool-call information.

ANAS Cloud provides backend endpoints for sessions and their messages.

### When you're not logged in

Cloud synchronization is skipped.

The conversation continues locally within the current process.

### When synchronization fails

ANAS CLI reports a cloud synchronization error.

The local conversation remains available in memory while the process is running.

A failed synchronization should not be treated as a successfully saved cloud conversation.

## Local sessions vs. cloud sessions

| Feature                             | Local sessions | Cloud sessions              |
| ----------------------------------- | -------------- | --------------------------- |
| Available during current process    | Yes            | Yes, after loading          |
| Listed by `/history`                | Yes            | Not directly                |
| Available through `/resume`         | Yes            | Yes, when authenticated     |
| Survives closing the CLI            | No             | Yes, if successfully saved  |
| Requires ANAS Cloud login           | No             | Yes                         |
| Requires internet access            | No             | Yes                         |
| Stored in persistent local database | No             | No, stored in cloud backend |
| Supports continued conversations    | Yes            | Yes, after restoration      |

## Authentication and access

ANAS Cloud session operations use account-based authentication.

Protected cloud requests require a valid CLI access token.

CLI access tokens have a 30-day expiration period.

The backend uses the authenticated account to determine access to protected cloud resources.

Cloud session access should not be confused with local conversation history.

See [ANAS Cloud](/docs/guides/anas-cloud) and [Security](/docs/guides/security).

## Sessions and agent memory

Sessions store conversation messages.

Agent memory stores information intended to remain useful beyond a single conversation.

These systems serve different purposes.

| Sessions                       | Agent memory                            |
| ------------------------------ | --------------------------------------- |
| Store conversation history     | Store reusable context                  |
| Track individual conversations | Can be shared across conversations      |
| Support resuming chats         | Supports retaining relevant information |
| May synchronize to ANAS Cloud  | Has separate cloud integration          |

ANAS CLI includes a cloud memory endpoint.

However, the existence of this endpoint does not guarantee that automatic memory retrieval is fully integrated into every provider's agent loop.

See [Memory](/docs/guides/memory).

## Session commands

| Command    | Description                                |
| ---------- | ------------------------------------------ |
| `/new`     | Create and activate a new session.         |
| `/history` | List locally available sessions.           |
| `/resume`  | Resume an eligible local or cloud session. |
| `/exit`    | Exit the interactive chat.                 |
| `/help`    | Display available slash commands.          |

## Important limitations

### Local persistence

Local sessions are not automatically saved to a persistent local database.

### Process lifetime

Local session history is lost when the CLI process exits unless the conversation was successfully saved to ANAS Cloud.

### Cloud authentication

Cloud session listing and restoration require valid authentication.

### Network dependency

Cloud operations depend on the configured backend and network connectivity.

### Synchronization timing

Cloud synchronization is attempted after chat processing.

This does not guarantee that every message was successfully saved.

### Cloud availability

A session must have been successfully synchronized before it can reliably be restored from ANAS Cloud.

### Memory separation

Agent memory is not the same as conversation history.

Cloud memory integration should be verified independently from cloud session synchronization.
