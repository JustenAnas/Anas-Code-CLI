# Sessions & Conversation History

ANAS CLI organizes interactive conversations into sessions. Each session has a unique ID, creation and update timestamps, conversation messages, and shared agent memory.

## How sessions work

When you start an interactive chat, ANAS CLI creates a new session automatically.

Each session tracks:

* **Session ID:** A unique identifier.
* **Creation time:** When the session was created.
* **Last update:** When a message was added or the session was updated.
* **Messages:** The conversation history, including supported tool-call information.
* **Memory:** Agent memory shared across sessions within the current chat process.

## Start a new session

Use `/new` inside an interactive chat:

```text
/new
```

ANAS CLI creates a fresh session and makes it active. The previous session remains available in the current process.

Starting a new session does not automatically delete the previous session.

## View session history

Use `/history`:

```text
/history
```

The history list displays locally available sessions, including their IDs, last-update timestamps, and message counts.

**Important:** `/history` lists sessions held by the current CLI process. It does not list cloud sessions directly.

## Resume a previous session

Use `/resume`:

```text
/resume
```

ANAS CLI presents a selection menu containing eligible local sessions and, when you're logged in, available cloud sessions.

### Resume a local session

Select a session marked `[Local]` to continue its existing conversation within the current process.

Local sessions are stored in memory. They are not automatically saved to a persistent local session database, so they are unavailable after the process exits.

### Resume a cloud session

Select a session marked `[Cloud]` to retrieve its saved messages from ANAS Cloud.

Cloud session access requires a valid login. To sign in, use the CLI's `login` command.

```bash
npm run dev -- login
```

When a cloud session is restored, its saved messages and timestamps are loaded into a local session object.

System-role messages are excluded from the restored conversation history.

## Cloud synchronization

When you're logged in to ANAS Cloud, ANAS CLI attempts to synchronize conversation data after processing a chat interaction.

The synchronization process:

1. Saves session metadata, including the local session ID and working directory.
2. Derives a session title from the first user message, using up to its first 80 characters.
3. Saves the session's messages, including supported tool-call information.

Cloud synchronization is optional. If you're not logged in, the CLI skips this synchronization.

If synchronization fails, ANAS CLI reports a cloud-sync error. The local conversation remains in memory.

## Local sessions vs. cloud sessions

| Behavior                             | Local session | Cloud session                     |
| ------------------------------------ | ------------- | --------------------------------- |
| Available during the current process | Yes           | Yes, when loaded                  |
| Listed by `/history`                 | Yes           | Not directly                      |
| Available through `/resume`          | Yes           | Yes, when logged in and available |
| Survives closing the CLI             | No            | Can be retrieved from the cloud   |
| Requires login                       | No            | Yes                               |

Cloud availability depends on successful authentication, network connectivity, and the configured cloud service.

## Session commands

| Command    | Description                                             |
| ---------- | ------------------------------------------------------- |
| `/new`     | Create and activate a new session.                      |
| `/history` | List sessions available locally in the current process. |
| `/resume`  | Choose an eligible local or cloud session to resume.    |
| `/exit`    | Exit the interactive chat session.                      |
| `/help`    | Display available slash commands.                       |

## Important limitations

* **Local persistence:** Local sessions are not automatically written to disk.
* **Process lifetime:** Local session history is lost when the process exits.
* **Cloud login:** Cloud session listing and restoration require authentication.
* **Network dependency:** Cloud operations can fail if the service or network is unavailable.
* **Cloud sync timing:** Synchronization is attempted after chat processing; it is not a guarantee that every message was successfully saved.
* **Memory is separate:** Agent memory is shared across sessions in the current process and may synchronize through the cloud. It is not the same as session conversation history.
