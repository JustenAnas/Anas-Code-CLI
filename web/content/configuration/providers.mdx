# AI Providers

ANAS CLI supports four AI providers. Configure the API credentials for your preferred provider to start using its models.

## Supported providers

| Provider   | Environment variable |
| ---------- | -------------------- |
| Claude     | `ANTHROPIC_API_KEY`  |
| OpenAI     | `OPENAI_API_KEY`     |
| OpenRouter | `OPENROUTER_API_KEY` |
| Gemini     | `GEMINI_API_KEY`     |

## 1. Configure your API key

Create a `.env` file in the root directory of your ANAS CLI project.

Add the environment variable for the provider you want to use:

```bash
ANTHROPIC_API_KEY=your_anthropic_api_key
```

For OpenAI:

```bash
OPENAI_API_KEY=your_openai_api_key
```

For OpenRouter:

```bash
OPENROUTER_API_KEY=your_openrouter_api_key
```

For Gemini:

```bash
GEMINI_API_KEY=your_gemini_api_key
```

Replace each placeholder with your actual API key. You only need to configure credentials for the provider you intend to use.

**Security reminder:** Never commit your `.env` file to version control or share your API keys publicly.

## 2. Select a provider

The guided startup experience includes a provider-selection step:

```bash
npm run dev -- wakeup
```

The provider factory supports these identifiers:

- `claude`
- `openai`
- `openrouter`
- `gemini`

The identifier used internally may differ from the provider's display name.

## 3. Troubleshoot API key issues

The current `doctor` command checks `ANTHROPIC_API_KEY` specifically. It may report that the environment is not ready even when another provider's API key is configured.

If you encounter a connection error:

1. Verify that your `.env` file is in the project root.
2. Check that the environment variable matches the selected provider.
3. Confirm that the API key is valid and has the required access.
4. Check the provider-specific error message.

Provider selection and credential validation depend on the current CLI implementation.
