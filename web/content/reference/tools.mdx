# Tools & Permissions

ANAS CLI uses tools to inspect project files, make changes, execute terminal commands, and inspect Git state. Tool availability depends on the selected mode and the current implementation.

## Available tools

| Tool          | Purpose                                               |
| ------------- | ----------------------------------------------------- |
| `read_file`   | Read a file.                                          |
| `write_file`  | Create or overwrite a file.                           |
| `edit_file`   | Replace exact text in a file.                         |
| `bash`        | Run a terminal command.                               |
| `glob`        | Find files using a glob pattern.                      |
| `list_dir`    | List directory contents.                              |
| `search_code` | Search project file contents.                         |
| `git`         | Inspect repository status, diffs, logs, and branches. |

## Tool access by mode

### Ask mode

Ask mode is restricted to read-only inspection tools.

**Available tools:**

- `read_file`
- `search_code`
- `glob`
- `list_dir`

File-writing, editing, terminal, and Git tools are not available through Ask mode's tool allowlist.

### Agent mode

Agent mode can access all eight registered tools, subject to permission checks and guardrails.

This enables the agent to inspect files, make code changes, run commands, and inspect repository state when permitted.

### Plan mode

Plan mode currently has no tools enabled through its tool allowlist.

It cannot invoke the registered tools through the current implementation.

## Permission prompts

ANAS requests confirmation before executing these operations:

| Tool         | Why confirmation is required           |
| ------------ | -------------------------------------- |
| `bash`       | A terminal command will be executed.   |
| `write_file` | A file may be created or overwritten.  |
| `edit_file`  | Existing file contents may be changed. |

The permission prompt displays the operation details and asks whether to allow it.

If permission is denied, that exact operation is blocked from being retried.

## Guardrails

ANAS applies additional checks before executing operations.

### Protected paths

File-writing and editing operations are checked against protected-path rules. Certain restricted changes require explicit authorization in the user's prompt.

### Destructive commands

Terminal commands are checked against destructive-command guardrails before execution.

### Repeated failures

ANAS stops retrying an identical operation after three failures.

## Safe usage practices

- Review permission prompts before approving operations.
- Read tool output carefully before using it to make decisions.
- Inspect file changes before committing or deploying your project.
- Verify terminal commands before allowing execution.
- Remember that tool access depends on the selected mode and current implementation.
