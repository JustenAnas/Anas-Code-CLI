# Tools & Permissions

ANAS CLI uses tools to inspect project files, make changes, execute terminal commands, search code, and inspect Git state. Tool availability depends on the selected interaction mode.

## Available tools

| Tool          | Purpose                                                                          |
| ------------- | -------------------------------------------------------------------------------- |
| `read_file`   | Read file contents.                                                              |
| `write_file`  | Create or overwrite a file.                                                      |
| `edit_file`   | Replace specific text in an existing file.                                       |
| `bash`        | Execute a terminal command using the Windows command shell.                      |
| `glob`        | Find files matching a glob pattern.                                              |
| `list_dir`    | List directory contents.                                                         |
| `search_code` | Search project files for matching code or text.                                  |
| `git`         | Inspect Git repository information, including status, diffs, logs, and branches. |

## Tool access by mode

### Ask mode

Ask mode is restricted to read-only inspection tools.

**Available tools:**

* `read_file`
* `search_code`
* `glob`
* `list_dir`

Ask mode cannot use its tool allowlist to write or edit files, execute terminal commands, or access the Git tool.

### Agent mode

Agent mode can access all eight registered tools, subject to permission checks and guardrails.

The agent can inspect files, make code changes, execute terminal commands, search the codebase, and inspect Git state when permitted.

### Plan mode

Plan mode currently has no tools enabled through its tool allowlist.

It cannot invoke registered tools through the current implementation.

## Permission prompts

ANAS CLI requests confirmation before executing these operations:

| Tool         | Why confirmation is required           |
| ------------ | -------------------------------------- |
| `bash`       | A terminal command will be executed.   |
| `write_file` | A file may be created or overwritten.  |
| `edit_file`  | Existing file contents may be changed. |

Review the operation details before approving a permission prompt. If permission is denied, the operation is blocked rather than being executed without authorization.

## Guardrails

ANAS CLI applies additional checks to help prevent unintended operations.

### Workspace and protected paths

File operations accept relative or absolute paths, subject to workspace-boundary checks. Paths outside the permitted workspace can be blocked.

Writing and editing operations also apply protected-path checks. Certain restricted changes may require explicit authorization in the user's prompt.

### Destructive commands

Terminal commands are checked against destructive-command guardrails before execution. Review the command and its effects before approving it.

### Repeated failures

ANAS CLI stops retrying an identical operation after three failures. If an operation repeatedly fails, inspect the error and adjust the approach instead of repeating the same attempt.

### Secret redaction

The `read_file` tool redacts detected secrets in file contents. This helps reduce accidental exposure, but should not be treated as a guarantee that every secret will be detected.

## Terminal command compatibility

The `bash` tool currently uses the Windows command shell (`cmd`), not a Unix shell.

For example, Windows commands such as these are appropriate:

```cmd
dir
type package.json
git status
```

Unix-specific commands, shell syntax, and flags may not work as expected.

## Safe usage practices

* Review permission prompts before approving operations.
* Check file paths before allowing file changes.
* Read tool output carefully before making decisions.
* Inspect code changes and Git diffs before committing.
* Verify terminal commands before allowing execution.
* Never assume a tool is available in every mode.
* Treat secret redaction as a safeguard, not a guarantee.

## Security and cloud authentication

Tool permissions and cloud authentication are
separate security controls.

Agent mode requires permission for terminal commands
and file modifications. Cloud OpenAI requests require
a valid CLI token and are subject to per-user rate
limiting.

See [Security](/docs/guides/security) for encryption,
authentication, rate limits, and known limitations.
